# v1 acceptance criteria

> The definition of "done" for the first complete release `(constitution-vs-roadmap)`.
> Each criterion has a **stable ID** (`F-1`, `I-4`, …). Roadmap issues ladder up
> to these IDs; the maintenance routine reads this file each run to compute what
> is still missing from v1, and decides **how** to get there itself.
>
> This file holds the **criteria** (durable) and the **authoritative per-ID
> status markers**. The markers are the source of truth for where v1 stands;
> live status is computed on demand from them plus actual repo / CI / ledger
> reality. There is no pinned status issue — when a marker drifts from reality
> it is corrected by PR.

## What `v1.0.0.0` means

> Pokémon Emerald is fully playable as a single-player game, from beginning
> through its optional and postgame content, with the observable experience of
> playing alone on mGBA.

That sentence is the binding completion gate (recorded rationale: issue #294).
**Fully ported means behavioural coverage, not structural translation**
`(behavioral-fidelity)`: every behaviour a lone player can reach must look and
feel the way a player sees it happen on mGBA, whatever shape the Rust takes to
get there — this is observable fidelity, not byte-for-byte parity. Upstream C
functions are not checklist items — reachable player-visible behaviour is.

**In scope:** everything one player reaches on their own cartridge — the main
story, the optional content beside it, and the postgame after the credits.

**Excluded:** multiplayer and link-only behaviour (link battles and trades, the
Union Room, record mixing, wireless play), *unless* single-player play reaches
shared upstream behaviour behind it — then that behaviour is in scope. Content
that merely resembles a link feature is not excluded by association: the Battle
Frontier and the Contest Hall are single-player content. Their save paths part
ways, though — the Frontier's `SaveGameFrontier` (`frontier_util.c:2421`; its
continue-warp call is at `:2431`) runs unguarded, so a lone player's Frontier save
reaches it and it is in scope, while the Contest Hall's continue-warp save
(`contest_util.c:618`) sits inside `Task_ShowContestResults`' `gLinkContestFlags
& LINK_CONTEST_FLAG_IS_LINK` branch, so only a *link* contest reaches it and it
is excluded with the other link paths.

Not everything excluded is multiplayer: behaviour no lone player can reach on an
**English retail cartridge** — the Japanese font sheets, dead upstream code with
no live caller — is excluded on that ground instead. Both grounds are exclusions;
neither is an excuse for a gap in reachable single-player behaviour.

Every exclusion is **recorded, never assumed**: in the ledger entry's own reason
(written through `scripts/ledger.py`, see `AGENTS.md`), naming which of the two
grounds it rests on, and — when it drops a whole criterion — as a ⊘ row in this
file citing the same reason. A behaviour missing without a recorded reason is a
bug, not an exclusion (`C-6`).

## Pre-1.0 milestones

`VERSION` keeps its `FINAL.MAJOR.MINOR.PATCH` shape; `RELEASE.md` is the
authority on which component a change bumps. Before `v1.0.0.0`, a `MAJOR` bump
— `v0.1.0.0`, `v0.2.0.0`, … — normally marks **meaningful playable progress
through the game**: rival battles, Team Aqua/Magma encounters, Gym Leaders,
major story events, the Elite Four and Champion, optional and postgame areas and
legendary encounters.

Those are **planning patterns, not a prescribed roadmap**
`(constitution-vs-roadmap)`. Milestones may be split, combined, reordered, or
added as development requires, and which one comes next is decided in GitHub
issues — not frozen here. Pre-1.0 milestones measure **progress**; only the
gate above defines **completion**.

## Integration — the early playable slice

The first slice the binary has to reach: `cargo build --release --workspace`
produces `pokeemerald-rs`, and it runs to the **title screen** → starts a **new
game** → plays the **protagonist's room** → the **first NPC interaction** → the
**first wild encounter** (a full battle) → the **first trainer fight** → then
**saves, exits, and reloads** cleanly.

This is a **pre-1.0 milestone**, not the definition of v1: these rows stay v1
criteria — necessary, not sufficient — and are the repo's current measurable
progress. Code and ledger comments that say "the v1 north-star path" mean this
slice.

## Single-player content — the v1 gate

Coarse, durable rows: **what** must be playable, never **when** or in which
order `(constitution-vs-roadmap)`. The named content is illustrative of each
row's reach, not a sequence to work through.

| ID | Criterion | Status |
|----|-----------|--------|
| C-1 | The main story plays end to end: new game → Elite Four → Champion → Hall of Fame → credits | ☐ |
| C-2 | The encounters along that path match upstream: rivals, Team Aqua/Magma, Gym Leaders, and the story events between them | ☐ |
| C-3 | Optional content off the critical path: side areas, sidequests, in-game trades and gifts, optional legendary encounters | ☐ |
| C-4 | Postgame content after the credits: the world is playable again once the credits roll, the Battle Frontier, and postgame legendaries | ☐ |
| C-5 | The systems a lone player uses throughout: party and PC storage, bag/shops/money, Pokédex, field moves, breeding, TMs, contests | ☐ |
| C-6 | Every recorded exclusion is multiplayer-only or otherwise unreachable by a lone player on an English retail cartridge, and carries a reason naming which; nothing single-player is missing by omission | ◐ |

`C-6`'s mechanical half is checkable: before it goes ☑, every ledger entry (or
sub-artifact) recorded as an exclusion — status `dropped` — must name its
exclusion class in its own reason, multiplayer/link-only or
unreachable-on-an-English-retail-cartridge. Entries dropped on some other
ground (a documented fidelity delta, content this port does not bundle yet)
have to be re-argued into one of those two classes or moved off `dropped`; the
row stays ◐ until they are. An exclusion argued inside a *non*-`dropped`
entry's reason — `graphics/fonts#latin` is `ported`, yet its reason excludes
the Japanese sheets and the two unused FRLG arrow sheets — is invisible to that
status sweep, so it is covered by the judgement half instead, not by the
mechanical one. The judgement half — that nothing single-player is
missing by omission — is what `V-7`'s coverage review and the `H-1` playtest
exist for.

---

**v1 ships when** every row is ☑ or a recorded ⊘, and `H-1` (the playtest) is
signed `(gated-by-default)` — that is, when someone can play Emerald alone on
this binary from the title screen through the postgame. Until then, `FINAL`
stays `0` and all releases are prereleases. **How** to reach each criterion is
the routine's call, planned through GitHub issues — not prescribed here
`(constitution-vs-roadmap)`.
